# Physics2D Checkpoint - August 30, 2026

## Outcome

The test area now has a real rigid-body simulation while retaining its sprite-led 2.5D presentation. [Box2D 3.1.1](https://github.com/erincatto/box2d/releases/tag/v3.1.1) is pinned as an implementation dependency and remains private to the `PhysicsWorld` module.

## PhysicsWorld interface

Callers use engine-owned definitions and generational `PhysicsBodyId` handles to:

- create box bodies with static, kinematic, or dynamic motion;
- set transforms, velocities, and kinematic targets;
- destroy bodies safely without allowing stale handles to mutate replacements;
- advance one fixed step and receive owned body snapshots plus contact/trigger events;
- collect engine-owned debug footprints for Render2D.

The implementation validates definitions before entering Box2D, maps gameplay X/Z pixels onto Box2D XY metres at 32 pixels per metre, converts results back to gameplay units, and copies transient Box2D event arrays before returning.

## Test-area integration

- GroundMap solid rectangles and world edges also create static physics footprints.
- The player is a controlled kinematic footprint synchronized after GroundMap resolves solid movement and discrete Y elevation.
- Trigger tag `1` is a Box2D sensor; the overlay is driven by buffered sensor events.
- A dynamic crate is pushed by the player, collides with static footprints, and synchronizes into World with render interpolation.
- Development builds project rotated static, kinematic, dynamic, and sensor footprints through Render2D using distinct translucent colors.
- Shipping builds compile those footprint diagnostics out.

GroundMap remains authoritative for discrete elevation and player wall sliding in this first slice. Box2D owns contacts, sensors, and dynamic-prop response. This avoids pretending a 2D rigid-body solver understands overlapping World Y levels before elevation-band rules are authored.

## Kinematic release correction

Box2D's target-transform helper retains the previous kinematic velocity when the requested target is already at the body's current position. `PhysicsWorld::set_kinematic_target()` now treats an effectively stationary target as an explicit stop and clears linear and angular velocity on that fixed tick. A regression test moves the player, releases movement, and verifies both the release tick and following idle tick remain stationary.
